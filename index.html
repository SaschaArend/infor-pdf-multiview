Unter der Haube

Entwickelt für Infor IDM v1 & v2 Security-Richtlinien.

Mit dem Wechsel auf Infor CloudSuite v2 Widgets (Connected Information) feuert das IDM keinen klassischen /search-Request mehr und blockiert fremde iFrames per strikter Content-Security-Policy (CSP). So löst die Erweiterung das Problem:

01 • MAIN WORLD HOOK

XHR & Fetch Interception

intercept.js wird per Manifest V3 direkt bei document_start in die MAIN-World aller Frames injiziert und erkennt sowohl klassische v1 /api/bc/search-Payloads als auch v2 SmallPreview/stream-Aufrufe.

const streamUrl = url.split('?')[0]
  .replace('/SmallPreview/stream', '/stream');
window.top.postMessage({
  type: 'INFOR_MULTIVIEW_PDF_URL',
  url: streamUrl, auth: authHeader
}, '*');
02 • SERVICE WORKER PROXY

CSP- & Auth-Header-Tunnel

Damit Chrome das PDF nicht wegen fehlender Session-Cookies oder X-Frame-Options ablehnt, lädt background.js den Stream samt abgegriffenem Authorization-Header im Hintergrund und wandelt ihn in Base64 um.

const fetchOpts = { credentials: 'include' };
if (request.auth) {
  fetchOpts.headers = { Authorization: request.auth };
}
const buffer = await fetch(url, fetchOpts)
  .then(r => r.arrayBuffer());
03 • TOP-WINDOW RENDERER

iFrame-übergreifendes Overlay

Egal wie tief das IDM-Widget in verschachtelten CloudSuite-iFrames sitzt: Das Dokumenten-Panel wird sauber im window.top gerendert und merkt sich die individuell gezogene Breite dauerhaft.

if (window !== window.top) return;
const lnTab = document.querySelector(
  'portal-tab-item[aria-label="LN"]'
);
if (lnTab?.getAttribute('aria-selected') !== 'true')
  return;
